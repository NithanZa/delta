# Delta MVP

## Outcome

A full research run works end to end from the command line: select snapshots by cutoff → extract facts → update hypotheses, timeline, strategy profile and open questions with `step-5-preview` → generate company-specific insights and actions → persist everything with a run log. Running Run 1, Run 2 and Run 3 in sequence against the Buffer corpus produces a hypothesis that is created, strengthened, then contradicted and revised.

## Step-by-step

1. Extend `src/lib/pipeline/schemas.ts` with:
   - `SynthesisOutput`: `{ timelineEvents: [{ eventDate, title, summary, factIds, relatedEventIds }], hypothesisUpdates: [{ hypothesisId | null, dimension, statement, change, confidence, reasoning, factIds }], strategyProfile: { customers, productDirection, positioning, distribution, businessModel } (each `{ summary, confidence, factIds }`), openQuestions: { resolved: [{ id, resolution }], new: [{ question }] } }`.
   - `InsightsOutput`: `{ insights: [{ title, whatHappened, whatItMeans, whyItMatters, whatToDoNext, severity, hypothesisIds, factIds, actions: [{ type, text, rationale }] }] }`.
2. Create `src/lib/pipeline/context.ts`: `buildCompetitorContext(competitorId)` loads company profile, research questions, active hypotheses (with their last update reasoning and any `userCorrection`), open questions, existing timeline events, and the facts from prior runs (compact form: id, date, category, statement). Also `formatForPrompt(ctx)` renders it as structured text with stable ids (`F12`, `H3`, `Q2`, `E5`) so the model can reference them.
3. Create `src/lib/pipeline/prompts/synthesize.ts` (model: `MODELS.deep`). The system prompt defines the rules: separate observed facts from inferred intent; every hypothesis update must cite fact ids; `change` must be one of created/strengthened/weakened/contradicted/revised; when contradicted and the evidence supports a new interpretation, emit a `revised` update with the new statement (code creates a new hypothesis row with `supersedesId`); confidence moves in proportion to evidence, never jumps to 1.0; user corrections are authoritative and must be respected; resolve open questions only when facts answer them; timeline events must link to earlier events when related; produce the strategy profile from all facts to date, not just new ones. User prompt = `formatForPrompt(ctx)` + the new facts from this run.
4. Create `src/lib/pipeline/prompts/insights.ts` (model: `MODELS.deep`). Input: company profile, priorities and constraints, the updated hypotheses (with what changed this run), the new facts, the new timeline events. Output: 2–5 insights that matter to *this* company, each with the four sections, severity, and 1–3 actions typed `respond` or `investigate`; `investigate` actions should include concrete questions for customer interviews or workflow comparisons where appropriate. Skip developments that do not affect the company.
5. Create `src/lib/pipeline/synthesize.ts`: `runSynthesis(run, ctx, newFacts, onProgress)` calls the synthesis prompt, maps ids back, writes `timelineEvents`, `hypotheses` + `hypothesisUpdates` (handle `created`, in-place status/confidence changes, and `revised` with supersede + retire of the old row), `strategyProfiles`, `openQuestions`. Then `runInsights(...)` writes `insights`. Validate that referenced ids exist; drop references that do not and log it.
6. Create `src/lib/pipeline/run.ts`: `startRun({ competitorId, label, cutoffDate })` inserts a `runs` row, then `executeRun(runId, onEvent)` performs: select → extract (phase 3) → synthesis → insights → finalize (`status = done`, stats `{ snapshots, facts, changes, hypothesesUpdated, insights }`). Every `onEvent` also appends to `runs.log`. On error set `status = failed`, `error`, and keep partial results. Wrap each LLM stage in a try/catch so a failed insight call does not lose the synthesis.
7. Create `src/lib/pipeline/presets.ts`: `REPLAY_RUNS = [{ label: "Run 1", cutoffDate: "2023-12-31" }, { label: "Run 2", cutoffDate: "2024-12-31" }, { label: "Run 3", cutoffDate: "2026-10-31" }]` (Run 3 cutoff moved to the fetch date so the 2026 agency case studies and the live pages are included) and `nextReplayRun(competitorId)` returning the first preset not yet run; after all presets are used, return `{ label: "Run N", cutoffDate: today }` so live URLs added later are picked up.
8. Create `scripts/run.ts` (CLI): `npm run run -- --competitor buffer [--label "Run 2" --cutoff 2024-12-31 | --next]`, prints progress lines and a summary of hypothesis changes and insight titles. Create `scripts/demo-reset.ts`: deletes runs and all derived tables (facts, timeline, hypotheses, updates, profiles, insights, questions) but keeps company, competitor, questions and snapshots.
9. Add `synthesize_hypotheses` and `generate_insights` canned mock outputs. Tests: `run.test.ts` with the mock client and an in-memory DB seeded with three small snapshots across cutoffs; assert that Run 1 creates a hypothesis, Run 2 strengthens it, Run 3 produces a `revised` update with `supersedesId` set and the old row `retired`, that the run log has events for each stage, and that a thrown insight stage leaves `status = failed` with the synthesis persisted.
10. Execute the three replay runs for real (`npm run demo:reset && npm run run -- --competitor buffer --next` three times). Read the outputs. If the agency hypothesis does not follow created → strengthened → contradicted/revised, adjust the corpus (phase 2 manifest) or the synthesis prompt, not the data. Record token usage per run in the run stats.
11. Commit.

## Acceptance criteria

- [ ] AC1: `npm run run -- --competitor buffer --next` completes Run 1 with `status = done`, at least 3 hypotheses, a strategy profile, at least 1 timeline event and at least 1 insight with actions.
- [ ] AC2: After Run 2 and Run 3 the hypothesis about agencies has an update history showing `created` → `strengthened` → `contradicted` or `revised`, and a `revised` row with `supersedesId` exists.
- [ ] AC3: Every hypothesis update, insight and timeline event stores at least one valid `factId`, and every fact id resolves to a row with a verbatim quote.
- [ ] AC4: `runs.log` contains ordered events for select, extract, synthesis, insights and finalize, and a failed stage results in `status = failed` with earlier stage output kept.
- [ ] AC5: `npm test` and `npm run check` pass.
